MusicToolkit 0.2.0 — перенос Яндекс Музыки и подборки в Apple Music

Для запуска через локального ИИ-агента начни с README.md и AGENTS.md.
Агент выполняет команды agent.py, готовит окружение и следит за прогрессом.
Ниже — подробная справка по ручному меню и базовому CLI.

Локальный инструмент для macOS. Один запуск через Start.command или команды
music_tool.py. Экспортирует метаданные Яндекса, ищет песни в приложении Music,
добавляет найденное в отдельный плейлист и распределяет медиатеку по подборкам.
Аудиофайлы не скачиваются. Apple Developer Program и ключ API не нужны.

Это ранняя версия для самостоятельного запуска. Перенос поддерживает
русские и английские подписи меню Music без ручного выбора языка.
Полный перенос ранее проверялся на одном Mac с русским интерфейсом Music;
английские подписи сверены с ресурсами Music, выбор команд проверен тестами.
Полный перенос в английском интерфейсе отдельно не прогонялся. Работа на других
версиях macOS, в других регионах и на больших библиотеках не гарантируется.

БЫСТРЫЙ СТАРТ

1. Нужны Mac, Python 3.9+ и приложение «Музыка» с выполненным входом.
   Python для macOS: https://www.python.org/downloads/macos/
   Для поиска в каталоге нужна действующая подписка Apple Music, интернет
   и русский или английский интерфейс Music. Язык определяется по доступным
   пунктам меню; язык системы и плейлистов менять не требуется.
   Сортировка существующих записей использует
   Automation и не зависит от языка названий меню приложения.
2. Распакуй архив в доступную для записи папку на Mac.
3. Открой Install.command: он создаст .venv рядом со скриптом и установит
   yandex-music==3.2.2. Для одной сортировки установка зависимости не нужна.
4. Открой Start.command. Если Finder не запускает .command, открой Терминал,
   набери cd и перетащи распакованную папку в окно, нажми Enter, затем:
       zsh Install.command
       zsh Start.command
5. Выбери «Проверить Mac». На запрос macOS разреши запускающему Терминалу
   управлять Music. Для переноса через поиск нужны также System Events
   в разделе «Автоматизация» и разрешение Терминалу в «Универсальном доступе».

ПЕРЕНОС ЯНДЕКС → APPLE MUSIC

1. В меню выбери «Экспортировать Яндекс Музыку».
   Подтверди вход на сайте Яндекса по выданной ссылке и коду.
   Токен входа хранится в памяти процесса и не записывается скриптом на диск.
   Экспорт: «Мне нравится» и собственные плейлисты. Чужие сохранённые
   плейлисты и сохранённые альбомы отдельно не экспортируются.
   API Яндекса неофициальный; вход или экспорт может перестать работать.
   Если экспорт частичный, успешные данные сохраняются, ошибки — в errors.
2. Результат: data/exports/<дата>/yandex_library.json.
   Не публикуй этот файл: он содержит твою библиотеку.
3. Выбери «Перенести экспорт». Меню предложит последний экспорт или попросит
   указать полный путь. Сначала создаст отчёт совпадений с уже имеющейся
   библиотекой, затем предложит запустить перенос с поиском в каталоге.
4. Новые песни добавляются в медиатеку и отдельный плейлист «ЯM».
   Плейлисты Яндекса не воссоздаются по отдельности: это общий архив.
   Во время переноса не переключай поиск/экран Music. Мак должен оставаться
   включённым; не запускай одновременно сортировку и второй перенос.
5. Сначала попробуй небольшую порцию: команда с --limit 5 ниже.
   Остановка: Ctrl+C. Повторный запуск того же экспорта с тем же data-dir
   продолжает обработку. Для другого экспорта нужен другой --data-dir,
   чтобы не смешивать сохранённые результаты.
6. Меню «Статус» или status --watch показывает сигнал, песню и шаг.
   Сигнал старше 15 секунд отмечается; шаг дольше 120 секунд вызывает
   ограниченный перезапуск. После трёх сбоев подряд без прогресса перенос
   останавливается. Подробности: data/transfer/transfer.log.

Статусы в data/transfer/catalog-progress.json:
  verified — совпавшая запись найдена и её наличие в плейлисте проверено;
  review — нет метаданных, несколько вариантов, другая версия/длительность;
  not_found — подходящая запись не найдена поиском;
  review_ui_error — три ошибки интерфейса при обработке конкретной песни;
  error/started — незавершённая попытка, будет проверена при продолжении.

После завершения проверь review/not_found/review_ui_error. Автоматический
повтор их не перезапускает. Для независимого повторного поиска можно задать
новый --data-dir: наличие записей в целевом плейлисте проверяется перед
добавлением. Число verified исходных записей может превышать число песен
в Apple Music, если несколько исходных записей сопоставились с одной песней.
Наличие в каталоге зависит от региона. Строгая сверка длительности до 3 с
может отклонять подходящие переиздания; неоднозначные версии не подменяются.

СОРТИРОВКА APPLE MUSIC

1. Выбери «Составить план сортировки всей библиотеки».
   Читается вся основная медиатека и все доступные пользовательские
   плейлисты, включая записи только в «Любимых песнях» и Shazam.
2. Открой data/sorting-plan.txt: там перечислены подборки и песни.
   JSON рядом — исполняемый план, привязанный к текущей медиатеке.
   Команда plan не меняет приложение. Для нового состояния используй
   plan --refresh. В меню снимок обновляется автоматически.
3. Проверь названия подборок и правила в rules.json. После изменения правил
   заново сформируй план. Команда apply читает уже сохранённый план.
4. Выбери «Применить план». Создаются только перечисленные в нём подборки.
   В существующие добавляются отсутствующие песни. Песни и подборки
   не удаляются, их порядок не перестраивается. Пересечения допустимы.
   «ЯM» и «Сейчас нравится» стандартными правилами не пополняются.
5. Повторное применение дополняет результат и пропускает уже имеющиеся
   записи. Одинаковые исполнитель, название, альбом и длительность с
   отклонением менее 1 с считаются одной записью. Другой альбом, ремикс
   или заметно другая длительность автоматически дублем не считаются.
6. После добавлений состав подборок повторно читается и проверяется.
   Результат: data/sorting-result.json. Прерванное применение можно повторить.

КАК РАБОТАЕТ СОРТИРОВКА

Это сортировка по метаданным, без прослушивания и без облачной нейросети.
Она не воспроизводит ручную экспертную разметку каждой конкретной библиотеки.
Жанровые метки Apple Music могут быть неточными. Песни без подходящего
правила предлагаются в «Разобрать» — их список виден до применения.

Стандартные категории: «Рок и инди», «Электроника», «Русский рэп»,
«Зарубежный хип-хоп», «Поп и соул», «K-pop», «Джаз», «Классика»,
«Кантри и фолк», «Саундтреки». Пустые категории не создаются.
Русский/зарубежный рэп определяется ориентировочно по жанру, написанию
исполнителя и редактируемому списку артистов. Это не определение языка аудио.

rules.json:
  genre_rules — точные названия жанров и соответствующие подборки;
  russian_rap_artists — известные латинские имена русскоязычных рэперов;
  rap_playlists — названия двух рэп-подборок;
  artist_rules — дополнительные подборки для исполнителей, включая дуэты;
  track_rules — уточнения конкретной песни и подборки по настроению;
  unmatched_playlist — куда предложить нераспознанные записи.

Например, элемент внутри track_rules:
  {"artist": "Пример исполнителя", "title": "Название песни",
   "playlists": ["Бодро"]}

Поле replace: true заменит жанровые назначения этой песни; по умолчанию
перечисленные подборки добавляются к ним. Необязательное поле album позволяет
уточнить запись. Названия remix/live в title не стираются.
«Бодро» и «Спокойно» автоматически по жанру не заполняются: для них нужны
явные track_rules. «Сейчас нравится» остаётся личным коротким списком.

КОМАНДЫ ДЛЯ ТЕРМИНАЛА

Открой папку инструмента в Терминале. Если .venv не создана, вместо
.venv/bin/python3 можно использовать python3 для команд без экспорта Яндекса.

  .venv/bin/python3 music_tool.py doctor
  .venv/bin/python3 music_tool.py export-yandex
  .venv/bin/python3 music_tool.py transfer "/полный/путь/yandex_library.json"
  .venv/bin/python3 music_tool.py transfer "/полный/путь/yandex_library.json" --apply --limit 5
  .venv/bin/python3 music_tool.py transfer "/полный/путь/yandex_library.json" --apply
  .venv/bin/python3 music_tool.py audit
  .venv/bin/python3 music_tool.py plan --refresh
  .venv/bin/python3 music_tool.py plan --source "ЯM"
  .venv/bin/python3 music_tool.py plan --exclude-playlist "ЯM"
  .venv/bin/python3 music_tool.py apply --dry-run
  .venv/bin/python3 music_tool.py apply
  .venv/bin/python3 music_tool.py status --watch

--source и --exclude-playlist можно повторять. Они сравнивают идентификаторы
записей; альтернативные издания одной песни могут иметь разные ID.
--data-dir — общий параметр ПЕРЕД командой:
  .venv/bin/python3 music_tool.py --data-dir "./data-second" transfer "export.json" --apply

ПРИ ОШИБКАХ

• «Music не ответил»: проверь приложение, интернет и разрешения macOS.
• Нет поля поиска/меню/альбома: поддерживаются русский и английский интерфейсы;
  изменение интерфейса Apple может потребовать исправления UI-моста.
  Подписи команд хранятся в engine/menu_labels.json. Сопоставление точное,
  с учётом разницы в регистре и типах пробелов. Неподходящие, отключённые
  и неоднозначные команды не нажимаются.
• Несколько плейлистов с одним именем: переименуй их, чтобы исключить выбор
  не того плейлиста. Для сортировки эта ситуация проверяется до записи.
• План другой медиатеки/песня исчезла: выполни audit и plan --refresh.
• Другой экспорт: сохрани прежний прогресс и используй отдельный data-dir.
• Если что-то не добавилось, изучи отчёт. Не обещается перенос 100% каталога.
