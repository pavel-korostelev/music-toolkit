# Spotify → Apple Music (экспериментально, 0.3.0-dev)

Проверены вход, полный экспорт небольшой библиотеки и полный цикл добавления
одной песни из каталога Music. Реальная пагинация больших списков и вложенные
папки пока НЕ проверены. Приватный API Spotify может измениться или ограничить доступ.
Пользователю не нужно вводить команды в терминале: их выполняет локальный агент.

## Первый запуск через агента

Передай репозиторий агенту и напиши:

> Прочитай AGENTS.md и docs/SPOTIFY.md. Подготовь отдельное окружение Spotify.
> Открой браузер для моего входа и прочитай небольшую выборку. Проверь результат,
> затем выполни полный экспорт лайков и плейлистов, включая вложенные папки.
> Покажи пропуски и предварительное сопоставление с Apple Music. Добавления
> пока не выполняй.

Агент выполняет:

1. `python3 agent.py setup-spotify --check`, затем при необходимости
   `python3 agent.py setup-spotify`. Нужен Python 3.10–3.13; агент выбирает
   существующий интерпретатор или готовит его отдельно. Яндекс остаётся на
   прежнем Python 3.9+ и `.venv`. Для явного выбора есть `--python /path/to/python`.
2. `python3 agent.py export-spotify` — только выборка: до 5 позиций в каждом
   выбранном списке, до 5 плейлистов и до 5 папок. Откроется отдельное окно
   Chromium. Человек входит на сайте Spotify обычным способом, включая
   необходимые проверки сайта. Пароль, cookies и токены нельзя передавать агенту
   в чат, аргументы команд или файлы. Сессия импортируется автоматически в памяти.
3. Процесс ждёт вход до 10 минут. Агент оставляет его работать и читает вывод.
   После выборки проверяет JSON: счётчики, ошибки, типы элементов, пропуски,
   идентификатор аккаунта. Выборка всегда имеет `mode=sample`, `complete=false`,
   код завершения 2; это не полная библиотека. При ошибках полного экспорта
   пока не выполнять.
4. После успешной выборки: `python3 agent.py export-spotify --full`. Потребуется
   повторный вход: сессия не сохраняется между процессами. Экспорт создаётся в
   `data/spotify/<SHA-256 аккаунта>/exports/<timestamp>/spotify_library.json`.
   Полный экспорт успешен только при `complete=true`, `mode=full`, пустом
   `errors` и согласованных счётчиках всех страниц. Код 2 означает выборку или
   неполный результат; код 1 — ошибку входа/подготовки, 130 — остановку.
5. `python3 agent.py doctor --music` проверяет доступ к Music. Пользователь
   подтверждает только необходимые системные разрешения запускающему приложению.
6. `python3 agent.py transfer-spotify --export /path/to/spotify_library.json`
   создаёт предпросмотр совпадений с существующей медиатекой, без добавления.
7. Только когда пользователь разрешил перенос:
   `python3 agent.py transfer-spotify --export /path/to/spotify_library.json --apply --limit 5`.
   Проверить статусы и фактическое наличие, затем продолжить тем же экспортом
   без `--limit`. Плейлист по умолчанию — `Spotify`; `--playlist` передавать
   последовательно. Исходные плейлисты объединяются в общий архив Apple Music.

`--data-dir` передаётся до команды и должен быть одинаковым во всех шагах.
`status-spotify --export /path/to/spotify_library.json` читает состояние нужного
аккаунта. Для другой независимой сессии с новым экспортом используй другой
`--data-dir` под `data/`, не удаляй старый прогресс.

## Формат и полнота

Общий адаптер `engine/sources.py` принимает старый `yandex_library.json` без
перезаписи и Spotify schema 2. Для Яндекса сохраняются прежние ключи прогресса
и точный формат идентичности с SHA-256 файла. Spotify использует `source_id`,
`source=spotify`, `account_id`, ключи `spotify:<account hash>:<track id>`;
Spotify ID никогда не записывается в `yandex_id`.

Нормализация учитывает наблюдаемые варианты ответа: `track._uri` у лайков
и `itemV2.data.trackDuration.totalMilliseconds` у плейлистов. Старый вариант
`duration.totalMilliseconds` сохраняется; отсутствующая длительность не заменяется.

Spotify schema 2 содержит `playlists`, `folders`, `library_pages`, `errors`:

- В каждом плейлисте: исходный URI, название, пути папок, список `tracks`,
  `skipped`, `counts` и `complete`. Позиции и повторы сохраняются в экспорте.
- В записи: ID, URI, ссылка Spotify, полное название (включая Live/Remix),
  исполнители, альбом, длительность в миллисекундах, позиция и доступность.
- Локальные файлы, эпизоды/аудиокниги и неизвестные/удалённые элементы идут
  в `skipped` с позицией, доступным URI и причиной. Это учтённые позиции,
  а не перенесённые песни. Отдельно сохранённые альбомы, исполнители и шоу
  не входят в область экспорта и перечисляются в `skipped_library_items`.
- Недоступная в Spotify песня с метаданными или запись без нужных полей
  сохраняется с `review_reasons`; при переносе попадает в `review`.
  Отсутствующая длительность остаётся `null`. Аудио не скачивается.

Обход включает лайки и все доступные плейлисты библиотеки (собственные и
сохранённые), рекурсивно раскрывает папки, явно передаёт offset/limit.
Встроенный `PrivatePlaylist.get_library()` не используется: он читает только
первую страницу. Для него через клиент SpotAPI выполняется тот же read-only
`libraryV3` с offset и folderUri. Обход треков — `fetchLibraryTracks` и
`fetchPlaylist`. Счётчики проверяются на каждой странице; изменение totalCount,
повтор страницы, ранняя пустая страница, неизвестная форма, цикл папок,
превышение пределов или ошибка запроса оставляют `complete=false`.
Изменения библиотеки, не меняющие счётчик, полностью исключить нельзя:
снимок приватного API не транзакционный. До проверки на аккаунте схемы ответов
считаются экспериментальными, неподдерживаемые формы не угадываются.

Каждая прочитанная страница атомарно сохраняется с правами 0600. Ошибки
содержат фиксированные коды, без сырых ответов/исключений. Запрос ограничен
20 секундами, вызов чтения — 90 секундами; до 3 попыток при временных сбоях
с задержками 1 и 2 секунды. 401/403/429 в GraphQL завершают экспорт без
бесконечных повторов. Максимум 10 000 страниц на коллекцию и 10 000 папок.
Частичный экспорт сохраняется; повторный экспорт создаёт новую папку.
Продолжение импорта Apple Music использует прежний экспорт и сохранённый прогресс.
Частичный Spotify-экспорт разрешён только для предпросмотра.

## Сессия и сеть

Исследован SpotAPI `main` commit
[`cb862571574e1ddbf5f8975f58a4f61a0e3d2050`](https://github.com/Aran404/SpotAPI/tree/cb862571574e1ddbf5f8975f58a4f61a0e3d2050)
(метаданные версии 1.2.7). Это закреплённый синхронный код; async-v2 prerelease
не используется. Все runtime-зависимости закреплены в `requirements-spotify.txt`.
Установка выполняется в `.venv-spotify`, браузер хранится там же.
`websockets` закреплён отдельно: upstream импортирует его из `__init__`, хотя
объявляет optional extra. Экспортёр не открывает websocket и не управляет плеером.

Используется документированный импорт `Login.from_cookies`: cookies `sp_dc`,
`sp_key`, `sp_t` читаются из нового непостоянного браузерного контекста только
для Spotify. `Login.login()`, JSONSaver, сохранение пароля и CAPTCHA-сервисы
не используются. Логи сторонней библиотеки подавлены. Сессия живёт только
в памяти экспортирующего процесса; браузерный контекст закрывается после входа.
Нельзя включать DEBUG/PWDEBUG, сетевые трассировки или сохранять storage_state.

Необходимые обращения экспортёра:

| Адрес | Назначение |
|---|---|
| `open.spotify.com` и `/api/token` | HTML/config и токен браузерной сессии |
| `www.spotify.com/api/account-settings/v1/profile` | чтение username для разделения аккаунтов |
| `clienttoken.spotify.com/v1/clienttoken` | получение технического client token |
| `api-partner.spotify.com/pathfinder/v1/query` | только три перечисленные read-only операции |
| `open.spotifycdn.com/cdn/*.js` | публичные пакеты веб-плеера для поиска persisted-query hashes |
| `code.thetadev.de/ThetaDev/spotify-secrets/raw/branch/main/secrets/secretDict.json` | внешний публичный справочник параметров TOTP, используемый SpotAPI |

Последний запрос выполняется upstream через отдельный `requests.get(timeout=5)`,
без cookies, пароля или токенов аккаунта. Это внешняя зависимость доступности;
upstream имеет встроенный fallback. Полученный JSON не выполняется как код.
TLS-клиент Spotify ограничен allowlist методов/адресов/операций; автоматические
редиректы отключены. Изменение профиля, подписок, плейлистов и воспроизведения
через экспортёр блокируется. Браузер при обычном входе загружает ресурсы Spotify
и служб проверки входа; это отдельный пользовательский login flow, не CAPTCHA API.
При установке требуются GitHub, PyPI/files.pythonhosted.org и CDN браузеров Playwright.

`data/`, `.venv-spotify/`, cookies, session/storage-state, экспорты и логи
нельзя публиковать. Сборщик дополнительно отклоняет файлы сессий, экспорты
и JSON с ключами учётных данных. Исходники SpotAPI не включаются в ZIP.
