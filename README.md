# MusicToolkit

Перенос из Яндекс Музыки в Apple Music и распределение библиотеки по подборкам. Работает локально на Mac, поддерживает русский и английский интерфейсы приложения «Музыка».

**Можно просто передать ссылку на этот репозиторий или ZIP локальному ИИ-агенту и написать, что нужно сделать. Подготовку окружения, запуск и проверку результата выполняет агент.** Пользователю остаются вход в Яндекс на сайте и разрешения macOS, если они понадобятся.

## Запуск через агента

1. Открой агента, который умеет запускать команды и управлять приложениями на твоём Mac.
2. Передай ему [ссылку на репозиторий](https://github.com/westik86-sys/music-toolkit) или распакованный архив. Архив доступен через **Code → Download ZIP**.
3. Отправь запрос:

> Прочитай README.md и AGENTS.md в этом проекте. Перенеси мои «Мне нравится» и собственные плейлисты из Яндекс Музыки в Apple Music, в общий плейлист «ЯM». Подготовь локальное окружение самостоятельно и проверь первые пять песен перед продолжением. Затем проанализируй всю мою библиотеку и распредели её по жанровым подборкам; пересечения допустимы. Покажи состав предлагаемых подборок и уточни только действительно недостающие решения. Выполни уже согласованные действия, проверяй прогресс и фактический результат. От меня нужны только вход на сайте Яндекса и системные разрешения, если они понадобятся.

Можно начать с более узкой задачи:

> Прочитай AGENTS.md. Проанализируй мою библиотеку Apple Music, предложи распределение по плейлистам и покажи план. Перенос из Яндекса пока не нужен.

Дополнительные варианты запросов — [docs/PROMPTS.md](docs/PROMPTS.md).

### Какой агент подходит

Нужен **локальный доступ к macOS**: возможность читать файлы, запускать Python и обращаться к приложению Music. Подойдёт агент на твоём компьютере с такими инструментами. Доступность зависит от его настроек и предоставленных разрешений.

Облачный чат, который только читает GitHub или работает в удалённом Linux-контейнере, не сможет управлять Music на твоём Mac. Одной ссылки для него недостаточно.

## Что умеет

- Экспортировать метаданные «Мне нравится» и собственных плейлистов Яндекса через вход на сайте. Пароль вводится на стороне Яндекса.
- Сопоставлять песни с существующей медиатекой, искать остальные в каталоге Music, сверять исполнителя, название, версию и длительность.
- Добавлять найденное в медиатеку и общий плейлист. Проверять добавления и продолжать перенос после остановки.
- Читать всю библиотеку и все доступные пользовательские плейлисты, включая записи, которые есть только в «Любимых песнях» или Shazam.
- Составлять читаемый план сортировки, добавлять песни в несколько подходящих подборок и пропускать уже имеющиеся записи.
- Показывать агенту статус в JSON, время последнего сигнала и текущий шаг.

Аудиофайлы не скачиваются. Developer Program и ключ Apple Music API для этого способа не нужны.

## Что потребуется от человека

- Mac с установленным Music и выполненным входом в нужный Apple Account.
- Для поиска новых песен в каталоге — подписка Apple Music и интернет.
- Подтверждение входа в Яндекс по ссылке и коду, которые покажет агент.
- При запросе macOS — разрешения запускающему приложению на Automation к Music/System Events и Accessibility для управления интерфейсом. Агент объяснит конкретный запрос; предоставлять разрешения нужно в системном диалоге или настройках самостоятельно.

Python 3.9+ и локальную `.venv` агент проверяет и подготавливает. Если Python отсутствует и доступного способа установки нет, агент объяснит этот конкретный шаг. Терминальные команды пользователь вручную вводить не обязан.

## Ограничения

Это ранняя версия. Полный перенос ранее проверялся на одном Mac с русским Music. Для английского интерфейса подписи сверены с ресурсами приложения и проверены тестами; полный перенос в нём отдельно пока не прогонялся. Изменения интерфейса Music могут потребовать исправления UI-моста.

Экспорт Яндекса использует [неофициальную библиотеку yandex-music](https://github.com/MarshalX/yandex-music-api). Доступность её входа и API может измениться. Чужие сохранённые плейлисты и сохранённые альбомы отдельными коллекциями не экспортируются. Исходные плейлисты объединяются в общий архив; их структура отдельно не восстанавливается.

Перенос 100% каталога не обещается: доступность зависит от региона, а у записей встречаются другие названия, версии и длительности. Спорные совпадения остаются в отчёте. Обработанная запись и успешно перенесённая песня — разные показатели.

Сортировка использует метаданные и редактируемые правила. Она не прослушивает аудио. Неуверенные назначения предлагаются в «Разобрать». Для настроенческих подборок агент может подготовить дополнительные правила по конкретным песням и объяснить их приблизительный характер.

Во время поиска через интерфейс не переключай экран и поиск в Music. Оставь Mac включённым. Приложение может добавлять в медиатеку записи из плейлистов при их копировании в новые подборки.

## Для ИИ-агентов

Начни с **[AGENTS.md](AGENTS.md)**. Это рабочая инструкция с авторизацией, продолжением, обработкой частичных результатов и проверкой результата. Она действует и при загрузке ZIP. Для агентов, читающих `CLAUDE.md`, предусмотрен указатель на ту же инструкцию.

Единая неинтерактивная точка входа — `agent.py`. Основные команды выполняет агент:

```sh
python3 agent.py doctor
python3 agent.py setup
python3 agent.py doctor --music
python3 agent.py export
python3 agent.py transfer --apply --limit 5
python3 agent.py transfer --apply
python3 agent.py status
python3 agent.py plan
python3 agent.py apply --dry-run
python3 agent.py apply
```

`doctor` и `status` возвращают JSON. `setup` устанавливает зависимость в `.venv`, повторный запуск её не переустанавливает без необходимости. `export` публикует временный запрос входа в локальном `data/auth-request.json` и удаляет его после завершения авторизации. Токен доступа в этот файл не попадает.

`transfer` без `--apply` создаёт только отчёт. При отсутствии `--export` выбирается последний экспорт из текущего `data-dir`; при продолжении — экспорт с сохранённым SHA-256. `plan` всегда обновляет снимок перед составлением плана. `apply --dry-run` проверяет план без записи в Music.

Для отдельной сессии:

```sh
python3 agent.py --data-dir ./data/second-account transfer --export /path/to/yandex_library.json --apply
```

Подробная справка по основному CLI и правилам: [README.txt](README.txt).

## Данные и публикация

Экспорты, прогресс и локальные правила хранятся в `data/`, окружение — в `.venv/`. Эти папки исключены из Git. Не прикладывай их к публичным issue, коммитам и архивам: там содержатся названия песен, плейлистов и локальные идентификаторы. Краткий запрос входа Яндекса также является личным.

Чистый архив из отслеживаемых файлов создаёт:

```sh
python3 scripts/build_archive.py
```

Результат — `dist/music-toolkit-0.2.0.zip`. В GitHub можно также использовать стандартный **Download ZIP**.

## Разработка

```sh
python3 -B -m unittest discover -s tests -v
```

Тесты не изменяют аккаунты или медиатеку. На macOS дополнительно исполняется чистый AppleScript-обработчик сопоставления RU/EN-команд без обращения к интерфейсу. На других ОС эти проверки пропускаются.
